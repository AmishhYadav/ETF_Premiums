# Valve status per ETF-month

Generated by `uv run etfp export valve-status` from the `valve_monthly` table built by `uv run etfp build` (units data through 2026-11-13). Do not edit by hand; rebuild and regenerate. Rule: DECISIONS D33 and `src/etfp/features/valve.py`.

Legend: **O** open (units rose: a creation happened) · **·** closed (data present, units never moved although NSE refreshed the counts) · **R** redeeming only (units fell, never rose) · blank unknown (no units data, nothing to compare with, or NSE refreshed no fund's count that month). `closed` means *no creation happened*; for a fund at a large premium that is the evidence the valve was shut, but a fund with no premium can be `closed` just because nobody asked.

Daily data (NSE security master) starts 2024-02-05, so Feb 2024 only sees changes from that file on. Months before Feb 2024 need the hand-entered `units_monthly` table (R11); where it is empty they are blank (and the years are left out).

NSE refreshes units outstanding (`IssdCptl`) in batches about once a week, for all funds at once, not daily. A month's status is therefore dated by the batch that published the change: a creation in the last days of a month can show in the next month. No batch at all ran between 5 Feb and 14 Mar 2024, so Feb 2024 is unknown and the Mar 2024 changes may include February creations.
